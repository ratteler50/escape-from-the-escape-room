# Docs

Two kinds of document live here. **Current** ones describe the game and the code as they are, and
a change that makes one wrong updates it in the same pull request. **Records** say what was planned
or decided at the time, and stay as written (a status line or a dated update note at most).

## Current

| Doc | What it's for |
|-----|---------------|
| [`design.md`](design.md) | The game: premise, cast, the Employee Handbook's sections, design rules, how it's played, every room's puzzles and the puzzle dependency chart, the finale. Start here. |
| [`glossary.md`](glossary.md) | The words to use for things, in code, docs and commits. |
| [`adding-content.md`](adding-content.md) | How to add a room, a character, a dialogue tree or a puzzle, and which test tells you what's missing. |
| [`art/README.md`](art/README.md) | How the art is made, and where each piece's record is. |
| [`drafts.md`](drafts.md) | Lines marked `// DRAFT:` for the developer's opinion. Generated by `npm run drafts`. |

## Records

| Doc | What it's for |
|-----|---------------|
| [`milestones.md`](milestones.md) | The milestones M1–M6: each plan as it was decided, and the slices and pull requests that delivered it. |
| [`slices/`](slices/) | One doc per slice: its spec, then build notes from making it. |
| [`decisions/`](decisions/) | Why things are built the way they are: one decision per file, with the alternatives. |
| [`art/`](art/) | Each room's background, the characters, and the prompt packs the art was generated from. |
| [`audio/music.md`](audio/music.md) | How the music was shortlisted and picked. |
| [`prototypes/`](prototypes/) | Notes from throwaway prototypes (the art style). |
| [`screenshots/`](screenshots/) | Images for the README and slice notes. |

Outside `docs/`: [`README.md`](../README.md) (what the game is, running it, how to play),
[`CLAUDE.md`](../CLAUDE.md) (how the agent works on the project), [`CREDITS.md`](../CREDITS.md)
(every asset, its source and license).
