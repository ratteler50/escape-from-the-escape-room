# Slice 4 — CI on GitHub

**Status:** done · merged as PR #1 · **Milestone:** M1 (tooling)

Outcome: PR #1 was merged before the red/green check (a regular merge, before squash-only was set).
The check was then done on throwaway PR #2: red with merge BLOCKED on a planted failure, green after
the revert, closed unmerged. `main` is now protected (PR + CI required) and squash-only.

Renumbering: this slice was inserted before the dialogue work, so Reginald and dialogue trees are
now slice 5 and the rest of the Lair is slice 6.

## Why

From now on every slice lands through a pull request. CI makes the checks we already run by hand
(typecheck, tests, build) run automatically on every PR, so nothing an agent writes can be merged
red. This slice is also the first one done under the branch → PR → developer merges workflow.

## Spec

1. **Workflow** `.github/workflows/ci.yml`, triggered on pull requests to `main` and on pushes to
   `main`. One job on `ubuntu-latest`:
   checkout → set up Node (version from `.nvmrc`, with npm caching) → `npm ci` →
   `npm run typecheck` → `npm test` → `npm run build`.
   A newer push to the same PR cancels the run still in progress.
2. **`.nvmrc`** pins Node to the local major version (25), so CI and this machine run the same Node.
3. **PR template** `.github/pull_request_template.md`: link to the slice spec, what was
   play-tested, and a checkbox for the developer's play-test.
4. **CLAUDE.md** gains the Git and GitHub section (already drafted, uncommitted on `main`) plus a
   line on CI: a PR is only ready for review when CI is green.
5. **Branch protection on `main`** (asks for your OK separately, since it changes repo settings):
   require a pull request, and require the CI check to pass before merging. You stay able to
   override as the admin.

Out of scope: Playwright end-to-end tests (M2), deploying to GitHub Pages, linting/formatting.

## Acceptance checks

- On branch `slice-4-ci`, the PR's CI run goes green.
- **CI is proven to fail when it should:** a throwaway commit that breaks one test turns the PR
  red; reverting it turns it green again. (Like the architecture-guard check: a check that never
  fails proves nothing.) Both commits disappear in the squash merge.
- With branch protection on (if approved): GitHub shows the merge button blocked while CI is red.
- You review and squash-merge the PR.
